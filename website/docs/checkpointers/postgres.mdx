# `@ilmek/checkpoint-postgres`

A durable [checkpointer](/checkpointers/overview) backed by Postgres — for threads
shared across processes. No hard `pg` dependency: it talks to any
node-postgres-style client (`query(text, params)`), so a `Client` or `Pool` drops
in as-is.

## Install

<Tabs groupId="lang">
<TabItem value="ts" label="TypeScript">

```bash
npm install @ilmek/core @ilmek/checkpoint-postgres pg
```

`pg` is not a hard dependency — any client exposing `query(text, params)` works —
but it is the usual choice.

</TabItem>
<TabItem value="csharp" label=".NET (C#)">

A .NET Postgres checkpointer is **on the roadmap**. Until it lands, use the
[SQLite checkpointer](/checkpointers/sqlite) (`Ilmek.Checkpointer.Sqlite`) for
durable threads today:

```bash
dotnet add package Ilmek.Core
dotnet add package Ilmek.Checkpointer.Sqlite
```

</TabItem>
</Tabs>

## Usage

<Tabs groupId="lang">
<TabItem value="ts" label="TypeScript">

```ts
import { Pool } from "pg";
import { graph, channel, START, END, run } from "@ilmek/core";
import type { ChannelMap, StateOf } from "@ilmek/core";
import { PostgresCheckpointer } from "@ilmek/checkpoint-postgres";

/** Support state — one append-only channel of messages. */
const SupportState = {
  messages: channel.append<string>(),
} satisfies ChannelMap;

type SupportState = StateOf<typeof SupportState>;

const g = graph("support", SupportState)
  .node("agent", async (state, ctx) => ({ messages: ["hi"] }))
  .edge(START, "agent").edge("agent", END)
  .compile();

const pool = new Pool({ connectionString: process.env.DATABASE_URL });

const cp = new PostgresCheckpointer(pool);
await cp.migrate();
await run(g, { messages: ["hello"] }, { threadId: "conv-42", checkpointer: cp });
```

`migrate()` creates the two tables it needs (`ilmek_checkpoints`, `ilmek_journals`)
if absent. It is idempotent — safe to call on every boot — or you can run the DDL
yourself and skip it.

</TabItem>
<TabItem value="csharp" label=".NET (C#)">

There is **no .NET Postgres checkpointer yet** — it is on the roadmap. For durable
threads today, use the [SQLite checkpointer](/checkpointers/sqlite): open the file
and hand it to the run, and nothing else in your graph code changes.

```csharp
using Ilmek;
using Ilmek.Checkpointers.Sqlite;

using var cp = SqliteCheckpointer.Open("./agent.db");   // creates + migrates
var opts = new RunOptions { ThreadId = "conv-42", Checkpointer = cp };
await g.RunAsync(input, opts);
```

</TabItem>
</Tabs>

## Sharing one database

<Tabs groupId="lang">
<TabItem value="ts" label="TypeScript">

Pass `tablePrefix` so several apps can share a database without colliding:

```ts
new PostgresCheckpointer(pool, { tablePrefix: "billing" });
// → billing_checkpoints, billing_journals
```

The prefix becomes part of a table name, so it must be a plain SQL identifier
(letters, digits and `_`, not starting with a digit); anything else is refused
when the checkpointer is constructed. The default is `"ilmek"`.

</TabItem>
<TabItem value="csharp" label=".NET (C#)">

The .NET Postgres checkpointer — and its table-prefix option — is on the roadmap.
With the [SQLite checkpointer](/checkpointers/sqlite), a separate database file per
app gives you the same isolation today.

</TabItem>
</Tabs>

## Values Postgres cannot store

Checkpoints and journals live in `jsonb` columns, and `jsonb` cannot hold the NUL
character (U+0000): a checkpoint, interrupt payload, answer or step value that
contains one fails to write, with Postgres' `unsupported Unicode escape sequence`
error. Strip or encode NULs before they reach state or a step result if your data
can contain them. The SQLite checkpointer has no such limit.

## Bring your own client

The checkpointer never opens or closes a connection — you own the `Pool`'s
lifecycle. Any object with `query(text, params) => { rows }` satisfies its
`SqlClient` interface, so a custom pool or a proxied client works as long as it
speaks that shape. That includes [PGlite](https://pglite.dev) — Postgres compiled
to WASM, running in-process — which is handy for tests:

```ts
import { PGlite } from "@electric-sql/pglite";
import { PostgresCheckpointer, type SqlClient } from "@ilmek/checkpoint-postgres";

const cp = new PostgresCheckpointer(new PGlite() as unknown as SqlClient);
await cp.migrate();
```

## Testing the package

The package's own suite runs the shared checkpointer contract against real
Postgres SQL through PGlite (a dev dependency), plus a fake client for the wire
contract — no database needed:

```bash
cd ts && pnpm install && pnpm build
pnpm --filter @ilmek/checkpoint-postgres test
```

A live smoke test against a real server is skipped unless `DATABASE_URL` is set.
It imports `pg`, which is not a dependency of the package, so make `pg`
resolvable first (for example `pnpm --filter @ilmek/checkpoint-postgres add -D pg`,
without committing it):

```bash
DATABASE_URL=postgres://user:pass@localhost:5432/ilmek_test pnpm --filter @ilmek/checkpoint-postgres test
```
